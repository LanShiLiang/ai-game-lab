FROM YOUR REPO TO THE LAB

你负责创作，我们负责部署。

  1. 准备一个能玩的仓库

    把源码、封面与素材放到公开 GitHub 仓库。部署细节、操作说明、作者和素材许可统一写在仓库 README 中。

  2. 填五项资料，提交 Issue

    填写游戏名称、GitHub 链接、游戏介绍、后端与部署需求，创意特色选填。点击「到 ai-game-lab 提 Issue」，直接进入站长仓库的新建 Issue 页面，检查后点击 Submit new issue（提交新 Issue）。长草稿先复制粘贴。

  3. 等待审核与上线

    保留 Issue 链接，后续补充与审核都在这里。站长检查可玩性、授权和部署需求，通过后获取游戏并部署，再回复可玩链接。

还没开始制作？点击「提交设计想法」，直接在 Issue 里描述游戏目标、玩法和特色，无需提供游戏仓库。需要登录 GitHub。

部署前，作者需要检查什么？ ↗

完整的部署说明请放到游戏仓库 README 中。依赖后端的作品请在表单说明服务需求；图片、音频和脚本使用相对路径，确保放到网站子目录后仍能加载。前端不要包含密钥。

实现开始、暂停、结算和重开；切换标签页时暂停或停止渲染；支持窗口大小改变及全屏。操作、支持设备与已知问题也可在 README 说明。

封面与素材留在仓库或 Release 中，并在 README 说明来源和授权。完整教程：创建 GitHub Issue ↗
