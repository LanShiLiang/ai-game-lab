# AI Game Lab 体验验收 · 2026-10-07

目标：浏览大厅、投稿或想法，进入三款游戏，切换显示模式，实际游玩、暂停、结算与重开，再返回大厅。先更新线上基础版本并记录页面，再修复问题；最终版本经检查后推送部署。

## 操作流程与状态

| 步骤 | 玩家操作 | 复查状态 |
| --- | --- | --- |
| 1 | 大厅搜索与分类，挑选游戏 | 通过：复用卡片，未提前加载游戏逻辑 |
| 2 | 填五项投稿资料或提交无仓库设计想法 | 通过：直达 LanShiLiang/ai-game-lab 新建 Issue 草稿；长介绍可复制，无资源上传 |
| 3 | 内嵌开始，或进入全屏、铺满窗口、独立窗口 | 通过：三个游戏都可切换，游戏实例保持；全屏被拒绝时可退出窗口铺满 |
| 4 | 逐浪竞速选择赛道、真实驾驶、冲线与重开 | 通过：海滨 8 人与城市 16 人组队完整完赛，漂移和氮气有效；两浏览器联机邀请、发车与退出补位通过 |
| 5 | 轨道闪避移动、暂停、继续、结束与重试 | 通过：真实按键运行至结算，重试恢复三格护盾和倒计时 |
| 6 | 运输船移动、瞄准、开火、换弹、选枪、暂停、复活及重开 | 通过：本地真实键鼠，手机模拟触控；结算菜单可开始新局 |
| 7 | 返回大厅与重新选择游戏 | 通过：销毁旧 iframe，退出展开状态 |

## 发现的问题及处理

1. **P1 · 三款游戏普通页面超出屏幕。** 1280×800 初始页面的游戏区域从 y=353 延伸到 y=1073；轨道暂停和方向按钮需向下寻找。压缩页头、按视口计算游戏高度，轨道再按自身工具区域计算圆形画面尺寸。小窗口赛车和运输船使用紧凑准备页，开局按钮保持可见。复查完整画面、主要操作及阵营选择互不遮挡。证据：`artifacts/experience-20261007/before/*-embedded.png` 与 `after/*-embedded.png`。
2. **P1 · 运输船结算后返回菜单无法继续。** 已结束的对局仍显示「返回战场」，继续逻辑拒绝进入，却没有新的开始入口。本地结算返回改为离开旧对局、显示完整准备菜单；联机结算菜单隐藏无效的继续按钮，并保留房主重开。复查从结算菜单启动新局。证据：`before/fps-ended-menu.png` 及 `after/report.json` 的结算回归。
3. **P2 · 手机雷达盖住己方比分。** 360×780 开局截图中雷达与顶部计分栏重叠。雷达移至计分栏下方；移动端使用现有切枪按钮，避免随身武器列表与触控区域重复；操作按钮保持 44px 高。复查完整比分、摇杆输入及释放。证据：`before/fps-mobile-play.png` 与 `after/fps-mobile-play.png`。

同时将大厅网络错误提示改为玩家可理解的重试说明，移除开发命令提示。性能措施包括游戏延迟载入、菜单和暂停降低渲染、后台停止渲染、自动分辨率、HUD 降频、缩略地图缓存、模型下载缓冲及时释放及静态文件流式响应。

## 验证依据与限制

- 本次 `npm run check`：20 个测试文件、129 项通过；构建通过。
- `artifacts/performance/after.json`：投稿及全屏回归；本机 3D 游玩约 60 FPS、菜单约 15 FPS，赛车暂停不渲染，运输船暂停渲染调用约减少 75%。隐藏和全屏拒绝分支为明确模拟，原生全屏使用真实浏览器操作。

- `artifacts/fps/browser-report.json`：运输船现有浏览器回归，包含装备、瞄准、复活与房主重开。
- 手机为 Chrome 模拟设备，没有实体手机验收；GitHub 草稿链接使用拦截响应验证，没有投稿或发送消息。截图和完整报告在本地生成，不纳入源代码。

本轮发现的上述问题均已复查解决；这不代表所有设备、网络与未来内容永远没有可改进之处。线上版本可读取 `src/release.json` 确认提交，更新沿用原生产配置并保留旧发布目录以供回滚。
