# 独立游戏仓库与部署期装配

## 修正后的边界

先前 `433f2a0` 仅把游戏做成同仓库独立包，不满足「平台不能包含游戏项目源码」的要求。本版本将三款游戏连同专用后端、模拟、资源、测试与性能工具迁出当前平台工作树。保留 Git 历史，不强制重写旧提交。

平台只维护 `apps/web`、`games.json`、通用 SDK、`deployment/registry.json`、部署工具和通用网关。平台源码不 import 任意游戏模拟/渲染/房间实现。网关只按部署时校验的描述符启动游戏自己的后端，转发路径，不知道射击、赛车或机器人规则。

运输船的已验证 CPU 优化留在 `game-transport-ship`：空间索引、分块导航准备、路径缓存、人物不可变资源共享与对象复用。性能证据和游戏测试随独立仓库维护；拆仓不会在平台重写这些逻辑。真实浏览器 FPS 验证仍受当前执行环境限制，不把 Node CPU 测量表述为 FPS。

## 版本政策

注册文件为一个明确的可信仓库白名单；游戏条目必须引用白名单中的精确 HTTPS GitHub URL。非白名单、待确认发布或未经明确允许的本地来源都会被拒绝。`publication:pending` 是阻止未验证仓库获取的真实状态，不表示远程仓库已经存在。

`ref` 支持分支名、tag、完整 40 位提交 SHA、`release:<tag>` 和 `release:latest`。初始注册默认锁定已逐文件核对的远端 SHA；需要升级时先查询可用版本，再明确更新该 ref，也可选择分支或 Release 策略。浏览器发布生成的远端 SHA 与本地测试提交可能不同，已验证文件内容完全一致；部署锁始终使用实际远端 SHA。查询只在 `deploy:versions` / `deploy:prepare` 发生：

1. 更新仓库镜像并查询版本
2. 将所选 ref 解析为唯一完整 commit SHA
3. 后续获取、构建、校验全部使用该 SHA，不再跟随 main/latest
4. 在组合 release-lock.json 记录 requestedRef、commit、lockfile SHA、来源、构建来源与产物摘要

同一 ref 将来指向新提交时，下次部署产生新的锁与缓存，不改变已准备或正在运行的发布版本。

## 优先不可变发布产物

对应提交若有 GitHub Release 的完整产物、SHA-256 和来源声明，优先下载验证，来源声明必须绑定仓库 URL、游戏 ID、提交 SHA、依赖锁 SHA 和压缩包 SHA。Release tag 必须解析到部署已选择的同一提交。校验失败中止，不回退执行源码。

缺少完整发布产物时，只有 `allowSourceBuild:true` 的可信注册仓库才可回退源码构建。固定流程为 `npm ci --ignore-scripts` 和 `npm run --ignore-scripts build`，不读取远端自定义部署命令、不自动运行 install/prepare/prebuild/postbuild hooks。源码仓库自己的 build 是经注册策略明确允许执行的代码；不能把不信任的投稿仓库直接加入白名单。

构建进程只有 PATH/系统临时目录等基础环境和隔离 HOME/npm cache，不继承 GITHUB_TOKEN、云密钥或 NODE_OPTIONS。建议生产构建继续放在低权限隔离构建机。私有仓库认证使用部署账号正常的 Git 凭据助手；GitHub Release API 可用运行环境中的 GITHUB_TOKEN。令牌不写入仓库、注册文件、锁、产物或游戏进程环境。

## 状态与缓存都在平台仓库外

`--state-dir` 必须是平台仓库外的独立绝对路径，拒绝指向本仓库或其祖先/子目录。典型布局：

```
/srv/ai-game-lab-state/
  repositories/       Git 镜像
  cache/<id>/<key>/    校验过的版本化产物
  npm-cache/          固定依赖缓存
  work/               临时构建，结束后清理
  releases/<id>/      不可变组合发布
  run/                后端临时配置
  current             原子切换的符号链接
  previous            可回滚的上一版本
```

缓存键包含仓库、完整 SHA、package-lock.json 的精确 SHA-256、Node 版本、OS/CPU 架构和构建规则版本。同版本重部署会校验文件集合及摘要后复用缓存，不重新下载模型或编译游戏。缓存被修改会拒绝使用。变更依赖锁、源提交或工具链会产生新缓存。

归档在解包前拒绝越界路径、链接、特殊文件、隐私文件和超限展开尺寸。组合发布生成覆盖公共静态文件、后端代码、依赖及版本锁的完整 SHA-256 清单。激活和网关启动都要校验，避免准备后修改服务代码却仍冒用旧版本来源。

## 原子发布、失败与回滚

prepare 在新的 staging 目录完成全部游戏与平台装配，任一获取/版本/构建/校验失败都删除该 staging，不改变 current。成功后才重命名为完整 release。

activate 校验发布清单，真实启动并探测每个独立后端，探测后再校验文件未被改变，然后原子更新 previous/current。部署状态锁避免两个准备或切换操作同时修改状态；异常退出留下的 deployment.lock 应先核对 PID/操作状态，不能盲目删除正在使用的锁。

如果网关已运行，激活工具必须收到同一 PID/实例对目标版本的就绪确认；二次启动失败或超时会恢复 current/previous。无运行网关时只报告 selected / not-running，不声称已上线。常驻网关只观察本地 current，先加载、校验、预热新的完整静态/后端组合，再一次替换活动组合，随后关闭旧进程。失败继续提供原有组合，不在请求路径拉取 Git 或查询版本。回滚选择 previous，并执行同样的验证/预热流程；不需要重新下载代码。

游戏内存房间不会跨进程迁移。网关发现当前服务 health 的 rooms 大于零会拒绝切换，并保留现有玩家连接；预热后还会再次检查。先确认无人游玩，再由获得授权的运维执行激活。服务在运行中崩溃会被标记为不健康，不会暗中启动另一版本；生产监控应检查网关就绪状态，并由进程管理器处理重启，不能只检查 PID 是否存在。prepare、创建代码分支或推送仓库均不自动授权部署。

## 网络与旧站点兼容

- 大厅入口和 `/games/freight-fire/`、`/games/apex-rush/`、`/games/orbit-dash/` 保持
- `/api/fps/*`、`/fps` 转发到 FPS 自己的进程
- `/api/racing/*`、`/racing` 转发到竞速自己的进程
- 游戏专用服务只监听 `127.0.0.1` 动态端口；外部只访问通用网关
- 通用网关可继续监听现有反向代理上游端口；不需要开放新外部端口或改防火墙
- 后端接受 GAME_SERVER_PORT 和指向临时 JSON 文件的 GAME_SERVER_CONFIG；URL 前缀由 publicBaseURL 保留，网关兼容原有代理已经移除前缀的请求，也接受带完整前缀的直接请求

部署阶段按原始内容 SHA 缓存 gzip 派生资源，复用时验证解压内容，原始游戏产物不改动。网关对公共静态资源做流式发送、ETag/HEAD 和预压缩表示处理，不在每个请求里重新计算资源摘要。API 与 WebSocket 从同域地址访问，Host/Origin 传到游戏自己的校验逻辑；后端目录、配置文件与依赖不会成为静态公共路由。

旧单进程 scripts/racing-server.mjs / online:start 已退役。迁移需要先准备并验证新发布，在已授权的上线窗口更新进程启动命令为通用网关。保留旧完整发布和现有代理配置；无需破坏性数据删除或历史重写。

## 本地集成验证

新游戏仓库尚未远程可读时，可用一个不提交的外部 registry 副本指定准确本地 Git 仓库路径并标记 publication:local，显式带 `--allow-local`。这只验证部署流水线，不冒称已经从远端下载。测试缓存和装配结果仍在平台仓库外；不能把本地路径提交成生产仓库地址。

平台测试覆盖可信来源、版本锁/缓存、恶意归档、失败保持 current、原子回滚、纯平台边界、通用 HTTP/WS 网关和独立游戏组合。各游戏自己的回归由各自仓库执行。
